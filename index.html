原理与限制

✅ v2 修复“下载视频帧缺失、解码不了”：编码不再依赖 MediaRecorder 的实时录制（画布稍慢就会丢帧），改为 WebCodecs VideoEncoder 逐帧确定性编码 + 自带 MP4 索引封装，帧数与时间戳精确可控；解码直接解封装读取每一个样本；默认开启“编码后自动逐帧回读校验”，下载前就确认能完整还原，失败可一键加固重编。

工作流程

编码：文件 → Deflate 压缩 → 按帧切块 → 每帧 CRC32 → Reed-Solomon(GF256) 纠错 → 码字交织 → 像素块映射 → VideoEncoder 逐帧编码（VP9/H.264，恒定码率）→ MP4 封装（完整样本表）。兼容模式（无 WebCodecs 时）退回 MediaRecorder 并自动加倍帧冗余。

解码：MP4 解封装 → VideoDecoder 逐样本解码 → 像素块采样（用帧头黑白参考自动校准亮度范围）→ 低置信度标记擦除 → RS 纠错 → 帧 CRC → 按帧号拼回 → 整体 CRC → 解压还原。重复帧去重，坏帧可用副本救回。

为什么“视频更小”是有条件的

视频 = 载荷 + 纠错冗余 + 封装开销。文本/代码/日志/数据库等可压缩文件，先压缩再编码，视频可以远小于原文件；zip/jpg/mp4 等已压缩数据，信息论下限决定任何编码都不可能更小，界面会如实显示预估。想更小：提高密度、降低码率/容错/重复——但以信道体检仍为“可靠”为前提。

推荐组合

重要文件：稳健预设（4级灰度 + 高容错 + 重复2）。文本求最小体积：高密预设 + 信道体检显示“可靠”。4K/60fps 编码较慢属正常；所有计算均在本地完成，文件不会离开设备。
